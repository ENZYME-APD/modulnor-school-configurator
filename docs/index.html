Modulnor School Configurator

A browser-based 3D BIM configurator for designing modular school buildings from prefabricated volumetric units. Drag, snap, stack, and configure classroom and corridor modules — the app produces a live Bill of Quantities from every layout change.

📦Live BOM by trade 🔗Adosamiento counts 📐Corridor wall take-off 💶Fee estimate 📄CSV export 🗂️GLTF 3D export 💾Save / Load JSON

What it Does

The configurator runs entirely in the browser — no server, no login, no data sent anywhere. A session produces all the information needed for an early-stage procurement estimate and a 3D visualisation of the school layout.

The app operates on a set of prefabricated module types (classrooms, restrooms, corridors). Each module has a fixed footprint and a defined wall configuration. The BOM is derived from Excel-sourced material lists (bom.json) that are looked up per module type and per electrical / roof kit assignment.

Typical Design Workflow

1
Select a module type
Choose from the type dropdown in the toolbar — e.g. B1 for a middle classroom, A1 for a left-end classroom.
2
Switch to Build mode
Click the Build button. Your cursor is now in placement mode.
3
Click to place modules
Click on the floor to place the first module. Click on the face of an existing module to snap the next one directly against it.
4
Swap types via context menu
Right-click a module → Swap to… to change its type without moving it. Use this to refine end-cap modules (A/C types) as the row takes shape.
5
Align with OSNAP
Press Ctrl+D to activate OSNAP. Snap-drag modules by their vertices to align independently-placed groups precisely.
6
Assign electrical kits
Select a module → Properties Panel → choose an electrical kit from the dropdown. Hold Shift to multi-select and assign in bulk.
7
Assign roof kits
Same process — select modules and assign a roof type per module.
8
Run QC checks
Use the QC toolbar to visually verify: Elec (all kits assigned), Roof (all roofs assigned), Orient (corridor walls correct), Links (structural connections visible).
9
Review the BOQ panel
The panel on the right shows live material quantities grouped by trade. Check the adosamiento counts and corridor wall take-off.
10
Export
Export CSV for procurement, Save JSON for the next session, Export GLTF for coordination.

OSNAP Tool

OSNAP (Object Snap) works like a CAD snapping system — it locks the drag anchor to exact geometric points on the module's edges.

Workflow

1
Select modules + activate
Select one or more modules, then press Ctrl+D or cycle the Gizmo button to OSNAP.
2
Hover to preview
Move the cursor over the selected module(s). A coloured dot appears at the nearest snap point.
3
Click to begin drag
Click to anchor the drag to that exact snap point. Hold Alt before clicking to duplicate instead of move.
4
Hover target + click to drop
Hover over any other module — the snap dot moves to the nearest snap point on the target. Click to release.

Each snap type can be toggled independently via the checkboxes in the toolbar: End, Midpoint, Intersection, Perpendicular, Nearest, Centre.

The snap search radius scales with camera distance: threshold = cameraDistance × 0.03 in 3D view, or orthoHeight × 0.02 in Plan view.

Calculation: Module Dimensions

All modules use a single shared geometry: 6 m long × 2.44 m wide × 3 m tall. This is the canonical Modulnor standard unit derived from the shipping-container standard cross-section. The THREE.BoxGeometry instance is shared in memory across all placed modules of the same type.

ℹ️
The 2.44 m width is the standard internal clear width of a shipping container (external 2.438 m / 8 ft). The 6 m length corresponds to the half-length (20 ft container = 6.06 m nominal).

Calculation: Link Detection

Links are the structural connections at touching module interfaces. The algorithm is a pairwise O(n²) comparison over all placed blocks, running in src/bom/linkDetector.ts.

Step 1 — Proximity test

Compute axis-aligned bounding boxes for each pair (B1, B2) and expand B1 by 5 cm (expandByScalar(0.05)). Skip the pair if they don't intersect after expansion.

ℹ️
Why 5 cm? Modules placed face-to-face have exactly zero geometric overlap. The 5 cm tolerance captures intentional adjacencies even when modules are snapped together perfectly.

Step 2 — Vertical vs horizontal classification

Compute the vertical Y-axis separation: dy = |B1.y − B2.y|.

ConditionClassification
dy > 1.5 m AND overlap footprint > 0.2 m × 0.2 m→ Vertical (stacking) link
dy < 1.5 m AND both modules are classrooms→ Proceed to Step 3
ℹ️
Why 1.5 m? Module height is 3 m. Same-floor modules share Y = 0 m (dy ≈ 0). Modules on adjacent floors differ by exactly 3 m. The 1.5 m threshold sits cleanly between these two cases.

Step 3 — Horizontal link directionality

Transform the direction vector B2 − B1 into B1's local coordinate space (undoing B1's world rotation), then check:

|localDir.z| > 1.5  // the connection is along the short dimension
|localDir.x| < 5.0  // the connection is not beside the module (long side)
ℹ️
The thresholds come from the module geometry: short dimension = 2.44 m (Z), long dimension = 6 m (X). The test confirms B2 is front or back of B1, not beside it.

Step 4 — Wall count classification

Determine which side of each module faces the other (right if localDir.z > 0, left otherwise). Look up the blueprint's wall definition for that side:

Walls at jointLink TypeBOM item
0 walls (both B-type open ends)Standard linkLARGO_STANDARD
1 wall (one A- or C-type end)Panel linkLARGO
2 walls (both closed ends meeting)Simple linkNo additional BOM item
⚠️
Assumption: Only classroom group modules produce horizontal links. Corridors abutting classrooms are not counted as horizontal links — they are measured separately via the dynamic wall algorithm.

Calculation: Dynamic Corridor Walls

For each CorridorStructure module, the algorithm (src/qc/qcManager.ts — getDynamicWalls()) determines which of its four vertical faces are exposed (not abutting another module). Each exposed face contributes wall panel material to the BOM.

Method

Expand the corridor module's bounding box by 10 cm. For each neighbouring module at the same level (dy < 1.5 m) that intersects this expanded box, transform the direction vector into local space and suppress the face in that direction.

Wall dimensions per exposed face

Face direction (local)Dimension assumedReason
±X (short faces)2.44 m linearModule width (short dimension)
±Z (long faces)6.00 m linearModule length (long dimension)

The total is accumulated and emitted as BOM item REV-DYN-WALL (Corridor Dynamic Walls, in linear metres).

⚠️
Only CorridorStructure blocks generate dynamic walls. CorridorFloor blocks do not. Upper-floor neighbours (dy ≥ 1.5 m) do not suppress walls.

Calculation: Project Fee

The project fee is a simple sum of per-module unit costs:

totalFee = Σ blueprint[b.typeKey].cost  for all placed blocks
⚠️
Placeholder values. The current unit costs (€10 classrooms, €15 restrooms, €4–6 corridors) are indicative placeholders defined in src/data/blueprints.ts. They do not reflect real procurement costs and must be updated before using the fee estimate commercially.

Undo History

The undo stack captures a full scene snapshot before every state-changing operation (placement, deletion, move, type swap, kit assignment). Each snapshot stores per-block: type key, world position, world rotation, electrical kit, roof kit.

The stack is capped at 10 entries. On undo, the current scene is fully cleared and rebuilt from the snapshot.
